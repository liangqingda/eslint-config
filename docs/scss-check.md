# SCSS 排版检查 `liangqingda-check-scss`

ESLint 只处理 `.js` / `.ts` / `.tsx`，样式文件的排版没有任何工具兜底。这个包自带一个
**零依赖**校验脚本，把「样式块之间必须空行隔离」这类排版要求跨项目复用。

## 为什么不是 stylelint

stylelint 能覆盖同样的规则，但需要项目额外安装 `stylelint` + 共享配置，并且要单独接一条
命令。这个脚本零依赖、随 `@liangqingda/eslint-config` 一起装好，适合只想「保证块间空行、
别把选择器列表写断」的项目。需要更完整的样式规范（颜色写法、属性次序、禁用规则等）时，
再考虑引入 stylelint。

## 用法

安装本包后直接用 bin：

```bash
liangqingda-check-scss            # 默认检查 ./src
liangqingda-check-scss src app   # 检查多个目录
liangqingda-check-scss --all      # 检查当前目录下所有 scss / css
```

接到 `lint` 流程里：

```json
{
  "scripts": {
    "lint": "eslint . && liangqingda-check-scss src"
  }
}
```

## 检查项

排版：

1. **块间缺少空行**：上一块以 `}` 结束、下一行又开始新块（以 `{` 结尾）时，中间至少要空一行。
2. **选择器列表被空行截断**：`.a,` 和 `.b {` 之间插空行不会让 Sass 报错，但会让人误以为它们
   是两个块，后续按「`}` 后空行」拆文件就会拆错。
3. **连续多个空行**：两块之间只留一个空行。
4. **行尾空格**。
5. **文件末尾缺少换行**，或末尾多出空行。

类名（`1.7.0` 起）：

6. **非 ASCII 类名**：`.标题` 这类中文 / 全角符号类名直接报错。
7. **非法开头**：类名不能以数字或连字符开头（`.2col`、`.-card`）。
8. **下划线**：类名不用 `_`，包括 BEM 的 `.block__title`、`.block--modifier`；统一写
   `camelCase` 或 `kebab-case`。
9. **同一文件内风格混用**：一个文件里既出现 `.card-title` 又出现 `.cardBody` 就报错。
   单个小写单词（`.card`）两种风格都兼容，不参与判定。

注释内部不参与判断：块注释里出现 `}` 或 `,` 属正常写法，不会被误报。

## 边界

- 只做排版与类名书写，不做语义检查（嵌套层级、变量作用域、`!important`、「类名是否表达用途」
  「样式与数据长度的隐式耦合」不在范围内，这些留给 review）。
- 类名只解析**以 `.` 开头、占据一整行选择器**（`{` 结尾）的写法；`&__title` 这类父级拼接、
  单行内联的多选择器、`composes` 里引用的类名不在检查内。
- 扫描 `.scss` 与 `.css`，自动跳过 `node_modules`、`dist`、`build`、`coverage`、`.git`、
  `.next`、`.output`。
- 输出路径相对执行时的工作目录，便于在 CI 里定位。

## 升级说明

- `1.7.0` 新增第 6–9 项，已有项目升级后可能报出**存量**类名问题：能改名的直接改名，
  确实要保留的按类名规则统一（不要用 `eslint-disable` 那套思路绕，这脚本没有 disable 机制）。
- 类名规则对所有项目一致，不做按项目配置——需要不同风格时统一走 `camelCase` 或 `kebab-case`，
  不要混用。
